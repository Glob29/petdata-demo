```bash
tools/cloudflared.exe tunnel --url http://127.0.0.1:8790 --no-autoupdate
```

Бинарник cloudflared не хранится в репозитории: скачайте его с
https://github.com/cloudflare/cloudflared/releases и положите в `tools/`.

---

Демо-прототип коммерческого data-продукта:

1. **Nutrition DB** — корма, состав, нутриенты, упаковки, провенанс.
2. **Breed DB** — породы, физиология, шерсть, наследственные заболевания.

API отдаёт обе базы в JSON. В демо — 499 SKU (7 seed + 492 собраны агентом, 37 дублей слиты) и 30 пород (19 собак, 11 кошек); схема и пайплайн рассчитаны на тысячи SKU и сотни пород.

## Деплой на VPS

Данные намеренно **не хранятся в git**: в репозитории только код, схема и скрипты.
База живёт на сервере в томе `./data` и монтируется в контейнер как `/data/petdata.db`.

```bash
# локально: подготовить файл базы (схлопывает WAL)
node scripts/export-db.js

# на VPS: поднять код и базу
scp data/petdata.db root@IP:/opt/petdata/data/petdata.db
docker compose up -d --build
```

UI: `http://IP:8790/`, API: `http://IP:8787/v1/health`.
Подробно — [docs/deploy-vps-ru.md](docs/deploy-vps-ru.md).

## Быстрый старт

```bash
# 1. Собрать демо-базу (SQLite)
node db/gen-breeds-sql.js   # db/breeds-data.json → db/seed-breeds.sql
node db/import.js
node db/normalize.js
node db/classify.js
node db/compute-feeding.js

# 2. Запустить API
node api/server.js
# http://127.0.0.1:8787/v1/health

# 3. Проверить
node db/check-breeds.js     # целостность Breed DB
node api/test.js
```

Если база уже собрана агентом и вы не хотите её пересоздавать, породы накатываются отдельно:

```bash
node db/migrate-breeds.js   # идемпотентно, SKU не трогает
```

Фасовки, которые перечислены на странице, но не попали в базу при сборе:

```bash
node db/backfill-weights.js --dry-run   # посмотреть, что изменится
node db/backfill-weights.js             # применить (берёт данные из кэша страниц)
```

Цены по фасовкам и ₽/г на уже собранной базе:

```bash
node db/normalize-packages.js   # убрать дубли фасовок и цен, развернуть мультипаки (10×85 г)
node db/enrich-packages.js      # фасовки и цены из блока «Вес упаковки» на карточке
node db/compute-prices.js       # средняя цена упаковки и ₽/г

# добрать цены там, где их нет
node agent/collect-prices.js --all --apply            # 4lapy: sitemap + __NEXT_DATA__
node agent/collect-prices-magizoo.js --all --apply    # magizoo: бренд-страницы + JSON-LD
```

Сборщик цен берёт товарные URL из sitemap 4lapy, фильтрует по бренду в слаге,
читает `__NEXT_DATA__` карточки (там для каждой фасовки указан вес и цена) и сопоставляет
с нашими SKU по названию, виду и форме. Записываются только фасовки, которые уже есть у SKU.
Спорные совпадения не пишутся, а складываются в `agent/price-matches.json`.

Требуется Node.js 22.5+ (используется встроенный `node:sqlite`). Внешних зависимостей нет.

## Агент сбора

```bash
# собрать данные по брендам из agent/brands.json
node agent/collect.js

# нормализовать и классифицировать
node db/normalize.js
node db/classify.js
node db/compute-feeding.js

# проверить качество извлечения на gold set
node agent/eval.js

# посмотреть, что загружено
node agent/inspect.js

# собрать автономный HTML-отчёт
node agent/export-html.js
# → report/index.html
```

Агент проходит цепочку: `sitemap/каталог → карточка → JSON-LD + регулярки → нормализация → БД → FTS-индекс`.
Для каждого SKU сохраняются источник, URL, дата, уверенность и `extraction_run`.

Пилот 21.11.2026: **513 URL**, **158 новых SKU за проход**, **21 ошибка**. В базе **499 SKU**, **694 строки нутриентов**, **790 цен**, **108 SKU с расходом г/кг**, точность извлечения на gold set **23/23 (100%)**.

Сертификаты: агент ищет декларации/сертификаты на карточках и страницах качества. В пилоте открытых документов не найдено — созданы записи `status=not_found`. Это важный результат: на сайтах брендов сертификаты обычно не публикуются.

## Модель данных

### Nutrition DB

```
source → manufacturer → brand → product → package
                             ├→ product_nutrient → nutrient
                             ├→ product_ingredient → ingredient
                             ├→ product_additive → additive
                             ├→ claim
                             └→ feeding_guide
```

- `product` — SKU в конкретном рынке (`market`), а не «корм вообще».
- `product_nutrient` хранит значение, единицу, базис, тип (min/max/typical), источник и уверенность.
- Базисы: `as_fed`, `dm`, `per_1000_kcal`.
- `package` — вес, цена, регион, ритейлер, а также `total_weight_g`, `price_avg` и `price_per_g`.
- один `product` может иметь несколько `package`: карточка часто продаётся в нескольких
  фасовках (300 г, 1,5 кг, 10 кг). В API это массив `packages`, в UI и отчёте — диапазон. 

### Цена за грамм

Клиенту нужна не средняя цена упаковки, а **₽/г**: она позволяет сравнить фасовки и посчитать
бюджет кормления. Поля в `package`:

| Поле | Смысл |
|---|---|
| `total_weight_g` | вес всей упаковки: `weight_g × pack_count` (10 × 85 г = 850 г) |
| `price_avg` | средняя цена упаковки по снимкам цен, ₽ |
| `price_per_g` | `price_avg / total_weight_g`, ₽/г |
| `price_samples` | сколько наблюдений цены усреднено |

Считается скриптом `db/compute-prices.js` из `price_snapshot` — не правится вручную.

Метрики в API дают два взгляда на цену:

- `metrics.price_per_g`, `price_per_100g_protein` и т. п. — по **средним** ценам упаковок (стабильная оценка);
- `metrics.observed_offers` — минимум и максимум по **отдельным наблюдениям** цен,
  то есть «самое дешёвое предложение на рынке»;
- `metrics.best_value` — самая выгодная фасовка этого SKU.

У товаров с несколькими фасовками в названии остаётся размер варианта по умолчанию
(«…, 400 гр»), но в UI и отчёте такой хвост срезается — иначе он противоречит списку фасовок.
В API у товара есть `metrics.price_per_g` (диапазон по фасовкам) и `metrics.best_value`
(самая выгодная фасовка), у каждой упаковки — свои `price_avg` и `price_per_g`.

Источник цен по фасовкам — блок «Вес упаковки» на карточке ритейлера: там для каждого веса
указана цена за килограмм, из неё получается цена упаковки. Поэтому ₽/г не зависит от того,
какую фасовку ритейлер показал по умолчанию.
  Если несколько фасовок перечислены только на странице, они достраиваются
  из кэша: `node db/backfill-weights.js`.

### Breed DB

```
breed → breed_weight
      ├→ breed_predisposition → condition
      └→ genetic_test
```

- `breed` — высота, вес, жизнь, шерсть, брахицефалия, активность.
- `breed_predisposition` — риск + уровень доказательности A–D.
- `genetic_test` — ген, мутация, наследование.

## Что в демо реально, а что нет

**Реально:**

- 58 нутриентов с единицами и категориями;
- 7 seed SKU + 492 SKU, собранных агентом (Hill's 61, Grandorf 26, Whiskas 20, 4lapy 456, Мнямс 10, Monge 10, Perfect Fit 10, Felix 8, Royal Canin 7, Purina Pro Plan 14);
- 30 пород — 19 собак (лабрадор, немецкая овчарка, французский бульдог, йоркширский терьер, чихуахуа, такса, ши-тцу, мопс, померанский шпиц, мальтийская болонка, золотистый ретривер, кокер-спаниель, бигль, сибирский хаски, ротвейлер, боксёр, бордер-колли, доберман, джек-рассел-терьер) и 11 кошек (мейн-кун, персидская, британская короткошёрстная, бенгальская, канадский сфинкс, шотландская вислоухая, абиссинская, сибирская, русская голубая, сиамская, ориентальная);
- 711 фасовок (`package`) на 499 SKU: у 170 SKU несколько весов — в UI и отчёте показан диапазон, в API массив `packages`;
- 625 фасовок с ценой за грамм (410 SKU из 499): средняя цена упаковки и ₽/г считаются из снимков цен (`price_snapshot`);
- 3 SKU с ценами, диапазоном цен и экспертной оценкой качества белка;
- аллергены: 11 групп и 19 источников белка, фильтры `exclude_allergen` и `protein_source`;
- 108 предрасположенностей (уровни доказательности A–D) и 17 генетических тестов;
- провенанс: источник, URL, уверенность;
- пересчёт as-fed → DM;
- API и тесты.

**Ограничения демо:**

- у части SKU нет влаги/ME: это специально, чтобы показать `note: moisture_missing`;
- значения с карточек ритейлеров имеют confidence 0.6 и требуют проверки;
- физические параметры пород взяты из инфобоксов ru.wikipedia с номерами стандартов FCI; вес и продолжительность жизни кошек частично экспертная оценка (`source_id = 19`), см. [Породы: методика](docs/breeds-ru.md);
- нет цен, истории версий, авторизации по тарифам, rate limit;
- SQLite, не Postgres.
