# Две базы данных как коммерческий продукт

**Дата:** 21.11.2026  
**Фокус:** сначала данные, потом приложение.  
**Артефакты:** [schema.sqlite.sql](../db/schema.sqlite.sql), [schema.postgres.sql](../db/schema.postgres.sql), [seed.sql](../db/seed.sql), [API](../api/server.js), [OpenAPI](../openapi.yaml).

---

## 1. Смена фокуса

Раньше мы обсуждали приложение для подбора корма. Теперь предлагается другой порядок:

1. Собрать **две справочные базы**:
   - **Nutrition DB** — корма, состав, нутриенты, упаковки, производители.
   - **Breed DB** — породы, физиология, шерсть, вес/рост, наследственные заболевания.
2. Продавать их **по API** и как выгрузки.
3. Приложения (для владельцев, ветеринаров, клубов, ритейла) строить уже поверх API.

Это сильнее, потому что:

- база — переиспользуемый актив, приложение — лишь один из потребителей;
- API продаётся ритейлу, клиникам, интеграторам, госструктурам;
- одна и та же база питает несколько продуктов;
- данные накапливаются и становятся рвом.

**Главный принцип:** база — не «таблица ради таблицы», а **продукт с полями, провенансом, версиями и качеством**.

## 2. Что именно продаём

### 2.1 Nutrition DB

Единица — **SKU в конкретном рынке** (бренд + продукт + вес + страна), потому что рецептуры Royal Canin во Франции и России могут различаться.

Поля:

- идентификация: бренд, производитель, линейка, название, GTIN, рынок, язык;
- классификация: вид, этап жизни, размерная группа, форма (сухой/влажный), полнорационность, лечебный статус;
- состав: ингредиенты по порядку, проценты, добавки, E-номера;
- нутриенты: белки, жиры, углеводы, клетчатка, зола, влага, ME;
- витамины: A, D3, E, K, C, B1, B2, B3, B5, B6, B7, B9, B12, холин;
- минералы: Ca, P, Ca:P, Mg, Na, K, Cl, Fe, Zn, Cu, Mn, Se, I, Co;
- аминокислоты: таурин, аргинин, лизин, метионин, цистин, триптофан и др.;
- жирные кислоты: омега-3/6, EPA, DHA, арахидоновая;
- прочее: L-карнитин, глюкозамин, хондроитин, бета-каротин;
- упаковки и цены (опционально);
- провенанс: источник, URL, дата, уверенность, версия.

### 2.2 Breed DB

Единица — **порода**.

Поля:

- идентификация: вид, название, синонимы, FCI-группа, страна происхождения;
- физиология: высота, вес по полу, продолжительность жизни, размерная группа;
- шерсть: тип, длина, плотность, требования к грумингу;
- анатомия: брахицефалия, форма тела, предрасположенность к тепловому стрессу;
- активность и темперамент;
- наследственные заболевания: болезнь, риск, возраст начала, уровень доказательности;
- генетические тесты: ген, мутация, тип наследования, доступность теста.

### 2.3 Что не входит в MVP

- медицинские назначения и диагнозы;
- персональные данные владельцев;
- реальные цены по всем регионам (можно добавить позже);
- сырые фотографии упаковок (только ссылки/хранение).

## 5. Модель данных

Два домена, общие справочники.

### 5.1 Nutrition DB

```
source → manufacturer → brand → product_line → product → package
                                             ├→ product_nutrient → nutrient
                                             ├→ product_ingredient → ingredient
                                             ├→ product_additive → additive
                                             ├→ claim
                                             └→ feeding_guide
```

Ключевые решения:

- `product` — SKU, а не «корм вообще»;
- `market` — страна/рынок, потому что рецептуры различаются;
- `product_nutrient` хранит значение, единицу, базис, тип (min/max/typical), источник и уверенность;
- базисы: `as_fed`, `dm`, `per_1000_kcal`; в API пересчёт на лету;
- версионность: `valid_from/valid_to` (в демо — `valid_from`);
- `package` — вес, цена, регион, ритейлер.

### 5.2 Breed DB

```
breed → breed_weight
      ├→ breed_predisposition → condition
      └→ genetic_test
```

- `breed` — физиология и шерсть;
- `breed_weight` — вес по полу и возрастному этапу;
- `breed_predisposition` — риск + уровень доказательности A–D;
- `genetic_test` — ген, мутация, наследование.

### 5.3 Справочники

- `nutrient` — код, название, единица, категория;
- `condition` — болезнь/состояние;
- `source` — провенанс;
- `allergen_group` — группа перекрёстной реактивности;
- `protein_source` — конкретный источник белка (курица, индейка, говядина, рыба…);
- `product_protein_source` — привязка продукта к источникам с ролью, процентом и гидролизом.

Это позволяет фильтровать корма по аллергену: «без курицы» исключает всю группу `poultry`, а «с индейкой» ищет точное совпадение.

## 6. Покрытие и приоритеты

### MVP (12 недель)

- 500–1 000 SKU: 5–8 брендов, собаки + кошки, сухой + влажный;
- 50 пород: 30 собак + 20 кошек;
- 45–58 нутриентов;
- 10–15 заболеваний на топ-породу;
- API + админка импорта + coverage-дашборд.

### Цель через 6–9 месяцев

- 5 000–10 000 SKU: 30+ брендов, 3–5 рынков;
- 200+ пород;
- 60+ нутриентов;
- лабораторная валидация 200–300 SKU;
- платные пилоты с 2–3 клиентами.

### Приоритет полей

1. Белок, жир, клетчатка, зола, влага, ME.
2. Ca, P, Ca:P, Na, K, Mg.
3. Таурин, омега-3, EPA/DHA.
4. Витамины A, D3, E, C, B-группа.
5. Микроэлементы Fe, Zn, Cu, Mn, Se, I.
6. Аминокислоты и остальное.

## 7. Как собираем

1. **Реестр источников** — бренд, сайт, шаблон, тип парсера, лимиты.
2. **Сбор** — JSON-LD → HTML → PDF/OCR.
3. **Извлечение** — LLM по схеме + регулярки для таблиц.
4. **Нормализация** — единицы, базисы, синонимы.
5. **Валидация** — сумма 95–100%, DM, Atwater ±15%, кросс-проверка.
6. **Версия и провенанс** — каждое значение со ссылкой и датой.
7. **Ручная проверка** — low confidence, конфликты, новые SKU.

Для пород:

- FCI/AKC стандарты — физиология и шерсть;
- VetCompass — вес и продолжительность жизни;
- OMIA — генетические ассоциации;
- Agria — ветеринарные профили;
- породные клубы — уточнения.

## 8. Технология

### Production

- **PostgreSQL 16** (managed: Yandex Cloud, Selectel, AWS RDS, Neon);
- объектное хранилище для сырых страниц (S3-совместимое);
- API: FastAPI или Node (Fastify), контейнеры;
- API gateway: ключи, rate limit, квоты (Redis);
- метринг: `api_usage` по ключу/эндпоинту;
- бэкапы, PITR, read replica для аналитики;
- CDN для документации и статики.

### Демо в этом репозитории

- SQLite через встроенный `node:sqlite` (Node 24), без зависимостей;
- API на `node:http`;
- тесты — `node api/test.js`;
- схема Postgres — в `db/schema.postgres.sql`.

- Себестоимость сбора: 1–3 мин/SKU автоматически + 10–20% ручной проверки.
- 5 000 SKU: 3–4 месяца, 1–2 data-инженера.
- Инфраструктура на старте: $50–200/мес.
- Точка окупаемости: 10–20 платящих клиентов на Starter/Pro.

## 11. Риски

| Риск | Мера |
|---|---|
| Данные быстро устаревают | версии, алерты, регламент обновления |
| Ошибки в нутриентах | gold set, лабораторная сверка, confidence |
| Мало покупателей | сначала 2–3 пилота, потом разработка |
| Конкуренты (PawDiet, All About Dog Food) | ниша: API + породы + RU/EAEU |
| Смешение SKU разных рынков | `market` + GTIN + версия |
| Юридические ограничения | лицензии источников, договоры, дисклеймеры (без углубления) |
